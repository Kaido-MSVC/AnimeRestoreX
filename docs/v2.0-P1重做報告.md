## 1. 結論

**照 P1 計畫改寫後的新圖無法在 DML 上執行**：session 建立成功，但 `Run` 失敗。原因不是模型內容，而是 DML EP 不支援 dynamo 匯出的 `Reshape(allowzero=1)` 加 `-1`。Windows ML 1.28.3 有相同失敗。

加上一項語意不變的實驗修正（`scripts/fix_reshape_allowzero.py`）後，全部通過。這項修正**不在已定決策內**，所以沒有併進 `rewrite_pad.py`，要請使用者決定（§9）。除非另外註明，§4 起的結果都是「rewrite_pad + allowzero 修正」後的模型，稱為 **az 模型**。

| 模型族 | 只跑 rewrite_pad，DML | az 模型，DML | CPU | 與 PyTorch 的誤差（tile 256） | 判定 |
|---|---|---|---|---|---|
| v3 1×（noise0–3） | 失敗 | 通過 | 通過 | ≥ 140.66 dB，8 位元最多差 1 | 需要 allowzero 修正才能用 |
| v3 2×（noise0–3_scale2x、scale2x） | 失敗 | 通過 | 通過 | ≥ 140.35 dB，最多差 1 | 需要 allowzero 修正才能用 |
| art 4× 新圖 | 失敗 | 通過 | 通過 | ≥ 133.47 dB，最多差 1 | 符合退回規則；修正後能用，但慢 3.2 倍、VRAM 3.4 倍 |
| art 4× 舊圖（20250502） | 通過 | 不適用 | 通過 | ≥ 133.55 dB，最多差 1 | **建議採用** |

**4× 結論：用 20250502 舊圖。** 新圖未修正時無法執行，符合退回規則；修正後雖然正確，舊圖的效能仍明顯較好（§5）。只記錄結論，manifest 未改。

## 2. 原因：DML 的 Reshape

失敗訊息（v3 noise0，節點因模型而異）：

```
Non-zero status code returned while running Reshape node. Name:'node_Reshape_3225'
... MLOperatorAuthorImpl.cpp(2597) ... 8007023E
```

| 嘗試 | 結果 |
|---|---|
| art noise3_scale4x | 同樣失敗（`node_Reshape_5816`） |
| `--opt basic`、`--opt disable` | 同樣失敗 |
| Windows ML 1.28.3 | 同樣失敗 |
| 未改寫的原始 ONNX | 同樣失敗 |
| 清除靜態 shape 含 `-1` 的 `allowzero` | **成功** |

ORT 1.24.4 原始碼（commit `2d92497`）`OperatorHelper.cpp` 的 `ReshapeHelper::GetOutputShapes`：`allowZero` 為真時直接複製 shape，**不解析 `-1`**；只有 `else` 分支處理。dynamo 匯出的 Reshape 大多帶 `allowzero=1`。session 建立時不會走到這裡，所以「能載入」不代表能執行，這點 P0 的靜態檢查看不出來。

修正規則：`allowzero=1` 且靜態 shape 含 `-1`、不含 `0` 的節點改成 `allowzero=0`。依 ONNX 規格，`allowzero` 只影響 shape 中的 `0`，所以語意相同。含 `0` 與 `-1` 會 STOP；動態 shape 保持不動。

| 模型族 | Reshape | allowzero=1 | 改成 0 | 動態、未動 |
|---|---|---|---|---|
| v3（9 個） | 157 | 130 | 105 | 25 |
| swin_unet/art（14 個） | 153 | 108 | 54 | 54 |

動態的節點實際執行時沒有失敗，但未逐一證明其值都不含 `-1`。

## 3. rewrite_pad.py

- 修改：`edge` Pad 只在 pads 可證明 ≥ 0 時放行且不改動；負數、混合或無法證明時 STOP。其他 mode（reflect 等）一律 STOP。
- 自測 `test_rewrite_pad.py`：11 個案例全部 PASS（新增 reflect 正值、edge 靜態正／負／混合、edge 動態正／負）。
- 新版腳本 SHA-256：`193fba277eac490f89fc2d03e0fd87d3f7f5f5b5abdcb9a0e6d4b3a76e315e89`。實驗修正腳本：`e821c0ceaae8880ac36b13eaeff7677cf41060628f61bca9d4768d80fbd0f82f`。

| 項目 | 結果 |
|---|---|
| v3 9 個 | 全部 exit 0：1 個負數 Pad → Slice，20 個正值 Pad（16 edge、4 constant）不動 |
| swin_unet/art 14 個 | 全部 exit 0：1 個負數 Pad → Slice，14 個動態 Pad 證明 ≥ 0 |
| 三方雜湊（原始、腳本、改寫後） | 23 個重新從磁碟計算，0 個不符（`_work/p1redo/hashes.json`） |
| 舊 20250502 回歸 | 14 個重新改寫，輸出與 `models/manifest.json` 的雜湊完全相同 |
| 原始 vs az 模型，CPU | 6 個代表模型 tile 256 **逐位元相同** |

**副作用**：`models/manifest.json` 的 `rewrite_tool.script_sha256` 還是舊值，依指示未改。模型已就緒時 `fetch-models.ps1` 會提早結束，不受影響；乾淨環境或 `-Force` 會在 `Assert-Sha` 停下，而 `build.ps1` 會呼叫它。P2 改 manifest 時要一起更新。新版對舊模型的輸出相同，所以舊 4× 圖不需要重新改寫。

1.24.4 上**仍需要負數 Pad 改寫**：只加 allowzero 修正、不改 Pad 時，輸出完全錯誤（v3 noise3 PSNR 1.70 dB，art noise3_scale4x 2.84 dB）。

## 9. 進入 P2 前還缺什麼

**要先決定：**

1. **allowzero 修正是否納入流程。** 不納入，v3 就不能在 DML 上用（也沒有 4× 這樣的舊圖可退）。建議納入：併進 `rewrite_pad.py`，或獨立成第二步，並要有三方雜湊。兩者都會改變模型雜湊。
2. **確認 4× 用舊圖。** 建議是（§1）。
3. **模型範圍**：建議 1×／2× 用 v3、4× 用舊 swin_unet。
4. **自匯出模型如何散布。** `fetch-models.ps1` 目前從 nunif 的 zip 取檔，v3 不在裡面；要自行提供經雜湊固定的檔案，或讓使用者花約 1 小時匯出。

**DirectML 授權要重新審視。** 換到上游後 ORT 是 MIT，但 `Microsoft.AI.DirectML` 仍是 Microsoft Software License Terms，不是 MIT。第 1(a) 條允許隨自己開發的應用程式散布，限制條款的 e 款不允許單獨提供，也不得移除通知。這看起來比 Windows ML 的問題單純，但要審閱全文後再寫進 NOTICES 與 EULA；這裡不是法律結論。
