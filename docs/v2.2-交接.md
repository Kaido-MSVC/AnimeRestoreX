## 3. 已知問題

- **EULA 未獲微軟回覆**：見 §2。
- **887A0007**：v2.2 P1 強制 OOM 時第一次出現一次（v2.0 沒有），已歸類為 DeviceLost，照常復原。
- **審查列為下一版處理的項目**（`docs/v2.2-安全審查.md` §4、§5 第 4 項，`docs/v2.2-安全複查.md`）：
  - 可恢復的配置失敗還沒有一致的工作邊界錯誤處理（TileProcessor 部分暫存配置不在 bad_alloc 捕捉內）。
  - `ModelContract` 讀 manifest 時，double 轉 int 前沒有範圍檢查；manifest 沒有檔案長度上限。
  - Qt 外掛路徑沒有鎖定（沒有 `setLibraryPaths()`／`qt.conf`）；需要先控制啟動環境，不是圖片可觸發。
  - diagnostics 與 runtime details 可能含本機路徑；日後若加匯出 log，再做遮蔽。
  - 模型 SHA-256 與 ORT 開檔之間的 TOCTOU；只有加入外部模型或共用可寫模型目錄時才需要提高優先度。
  - `inflateLimited` 的 `inflateEnd` 不是 RAII，例外時會跳過（需要配置失敗條件）。
  - 不可 seek 的裝置仍可能先配置最多 32 MiB（ICC）／4 MiB（EXIF）才發現資料不足；正式入口都是檔案。
  - ICC 只確認解壓完整與大小，不做 ICC 格式驗證（原樣保留的既有策略）。
  - `tools/models-requirements.txt` 等沒有 pip hash（本機建置的可再現性）。
- **Qt 6.12.0 內附元件的公開 CVE**（libpng CVE-2026-46675 等）：未確認本程式可觸發，等 6.12.1。libjpeg-turbo 3.2.1 是否包含 CVE-2026-75466 的修補未核實。
- `tests/tst_inference_core.cpp` 的 C4456 警告（v2.1 P1 起，未修）。
- exe 沒有 VERSIONINFO；SHA256 檔是 CRLF（v2.0 起）。
- lupdate 會掃描嵌入的 `license.txt` 並印出 4 行括號警告（無害）。
- 2.1.0 的 `.package` 依賴紀錄在 v2.2 試做封裝時被覆寫，已無法取回（`docs/v2.1-交接.md` §5.3）。
- 只在 Windows 11 25H2 + GTX 1060 6GB 實測。

## 4. 工作規則

沿用 `docs/v2.1-交接.md` §4 與 `docs/v2.0-交接.md` §5，另加：

- 含反斜線的檔案只用 Edit；commit 不加 Co-Authored-By；不動全域工具和 PATH。
- `build.ps1` 會依序呼叫 `fetch-runtime.ps1`（預設 windowsml）、`fetch-models.ps1`、`fetch-zlib.ps1`；third_party 底下的內容都不進 git。
- 試做封裝：版本號未改時一律加 `-Suffix`；`package.ps1` 遇到已存在的輸出會停止，不要用 `-Force` 繞過。
- GPT 等其他工具寫的審查報告：先原樣 commit，修正前先讀程式碼確認問題存在，修正紀錄附加在報告最後、原內容不動。
- smoke test 的 EULA：agent-desktop 的鍵盤操作需要程式在前景；不在前景時，用對該程序視窗投遞訊息（WM_KEYDOWN、WM_LBUTTONDOWN）的方式，不用實體輸入。Qt 下拉選單的無障礙「選取」不會確認選項，需展開後投遞方向鍵與 Enter。「關於」是 modal，開著時 UIA 會逾時。
- 回歸基準：`_work/v220rel`（2.2.0 封裝前的輸出，與 v2.1.0 逐位元組相同）。
