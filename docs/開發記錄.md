## 3. 上游 CLI 實測行為（20250915，本機）

`-h` 實際輸出的參數：`-n -1/0/1/2/3`、`-s 1/2/4/8/16/32`、`-t >=32/0=auto`、`-m`、`-g`（`-1` 表示 CPU，預設 auto）、`-j`、`-x`、`-f jpg/png/webp`。

| 情境 | exit code | stderr | 程式處理方式 |
|---|---|---|---|
| 正常 2×、4× | 0 | 只有 GPU 資訊行 `[0 NVIDIA ...]` | 驗證輸出檔尺寸是否剛好為 W·s × H·s |
| 模型路徑不含 `models-cunet` | -1 | `unknown model dir type` | 上游以路徑名稱判斷模型類型，所以安裝資料夾名稱必須固定為 `models-cunet` |
| 輸入檔解碼失敗 | **0** | `decode image ... failed` | exit code 不可靠；以「輸出檔存在且尺寸正確」判定成功 |
| GPU 編號不存在 | -1 | `invalid gpu device` | 轉為「找不到可用的 Vulkan GPU」訊息 |
| 中文、日文、空白路徑 | 0 | — | 可正常處理（主控台輸出的路徑會亂碼，不影響處理） |

## 4. 決策記錄

| 日期 | 問題 | 證據 | 決策 | 影響 |
|---|---|---|---|---|
| 2026-11-01 | MSVC 工具集 | VS 預設檔為 14.51.36231；另有 14.52 | 使用者選定 14.51.36231 | `build.ps1` 固定 `-vcvars_ver=14.51` |
| 2026-11-01 | 輸出命名 | 使用者選定 | `原名_2x.ext`，撞名時加 ` (1)`、` (2)`… | `QFile::rename` 不會覆寫既有檔案 |
| 2026-11-01 | 失敗判定 | §3：解碼失敗時 exit code 仍為 0 | 成功需同時符合：exit code 0、輸出存在、尺寸正確、編碼完成並改名成功 | 不會把未處理的圖片算成成功 |
| 2026-11-01 | GPU 選擇 | `-g` 預設 auto；`-1` 為 CPU | 不傳 `-g`，不開放 CPU 選項 | 規格不要求 CPU 備援 |
| 2026-11-01 | alpha | 規格 §3.2 | 只有確實含透明像素（alpha < 255）才以 RGBA 送入 waifu2x；PNG／WebP 保留 alpha；JPEG 合成白底 | 全不透明的 RGBA 圖片視為 RGB 處理 |
| 2026-11-01 | 色彩 | 規格 §3.2「最小且一致」 | 內嵌非 sRGB 描述檔時先轉成 sRGB；輸出一律不嵌入 ICC（視為 sRGB） | 不做完整色彩管理 |
| 2026-11-01 | APNG | Qt PNG 讀取器只讀預設影格 | 在 IDAT 之前掃描 `acTL` chunk，有則拒絕 | 不會只取第一格就悄悄處理 |
| 2026-11-01 | 子行程收尾 | 規格 §8 | 取消時呼叫 `kill`；另用 Job Object（KILL_ON_JOB_CLOSE），GUI 異常結束時也會一併終止子行程 | — |
| 2026-11-01 | PNG 單邊上限 | 無有文件依據的限制 | PNG 不另設單邊上限，只檢查總像素 | 極端長寬比若在讀寫時失敗，會以錯誤回報 |

## 5. A9 實機量測步驟（GTX 1060 6GB，由使用者執行）

準備：一張小圖（約 0.3 MP）和一張接近 4.5 MP 的動漫插畫（例如 3000×1500 或 2100×2100）。先執行 `build.ps1 -Preset release`。

1. 開啟工作管理員的「效能 → GPU」頁籤，觀察「專用 GPU 記憶體」；「詳細資料」頁籤加入「認可大小」欄。
2. 純推論耗時：在 PowerShell 執行下列指令。把 `<in>` 換成圖片路徑，`s` 分別用 2 和 4，`t` 分別用 0（自動）、200、100：
   ```powershell
   $w="D:\projects\AnimeRestoreX\build\release\waifu2x"
   Measure-Command { & "$w\waifu2x-ncnn-vulkan.exe" -i <in> -o "$env:TEMP\a9.png" -n 1 -s 4 -t 0 -m "$w\models-cunet" }
   ```
   執行期間記下專用 GPU 記憶體峰值，以及 waifu2x 行程的記憶體峰值。
3. 端到端：用 release 版 AnimeRestoreX 處理同一張圖。輸出 PNG 4× 和 WebP 4×，用碼表計時，並記下 AnimeRestoreX.exe 的記憶體峰值。
4. 確認 4.5 MP 輸入以 4× 輸出得到 72 MP（例如 12000×6000）；4500×1000 選 WebP 4× 時應在處理前就被拒絕。
5. 放大檢視 4× 結果，看是否有 tile 接縫，特別是 `-t 100` 的結果。
6. 降噪 0／1／2／3 各輸出一張，比較後告訴我預設值要用哪一級。

請回報：圖片尺寸、`-s`、`-t`、耗時、VRAM 峰值、RAM 峰值、是否有接縫或錯誤訊息。
