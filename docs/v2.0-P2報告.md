主要介面：

```cpp
Status makeTilePlan(int w, int h, const TileParams&, int tile, TilePlan&);
Status upscaleImage(const ImageView& in,                 // 8-bit RGB/RGBA，自訂 stride
                    const TileParams& rgbModel, ITileEngine& rgbEngine,
                    const TileParams* alphaModel, ITileEngine* alphaEngine,
                    const ProcessOptions&,                 // tile、OOM 重試、取消旗標、進度回呼、輸出上限
                    Image8& out, ProcessStats*);
```

設計決策：

1. **replicate padding 以座標 clamp 實作**，不建立整張補邊後的影像。數學上等同上游的 `F.pad(..., mode="replicate")`。
2. **seam blending 採「累加 Σ(y·f) 與 Σf，最後再正規化」**（照你的指示）。上游是逐 tile 增量正規化（`pixels = pixels·W/(W+f) + y·(1−W/(W+f))`），兩者是同一個加權平均，只有 float 捨入不同。實測與上游的差 ≤ 1 LSB，而且不集中在接縫（§5），所以這個差異可以接受。
3. **累加緩衝區只配置最終裁切範圍**（W·s × H·s），落在範圍外的 tile 輸出直接丟棄。上游配置的是補邊後的 `input_h·s × input_w·s`，結果相同，但我方比較省記憶體。權重只用 1 個通道（上游 3 個通道的值都一樣）。
4. **非法 tile 在任何 Run 之前就回傳 `InvalidTileSize`。** 上游 `_find_valid_tile_size`（`nunif/models/model.py:54-62`）會靜默往下找合法值；我方依 P1 的決定改為直接報錯，不自動調整。
5. **只有 `OutOfMemory`（HRESULT 0x8007000E）可以重試一次**，用 fallback tile（預設 160）從乾淨狀態重算整張圖；手動 tile 不重試。`DeviceLost`（887A0005／0006／0007／0020）直接回傳，不重試。任何錯誤或取消都會清空輸出，不留下部分結果。
6. **取消**：每個 tile 開始前檢查 atomic 旗標。CPU 路徑由呼叫端另外呼叫 `requestTerminate()`，中斷正在執行的 Run（DML 不支援，P1 §6.6）。
7. **進度**：每完成一個 tile 回呼一次。內容是有效像素（每個 tile 不重疊的輸出份額，總和剛好等於 W·s·H·s，含 alpha 時再乘 2）、tile 數與第幾次嘗試。
8. **溢位**：輸出像素、位元組數、累加緩衝區大小都用 uint64 檢查乘法溢位；`maxOutputPixels` 預設 75,000,000（規劃 §8.1）。配置失敗回傳 `SizeOverflow`，不會當成 OOM 重試，因為縮小 tile 對主機記憶體沒有幫助。
9. **數值防護**：模型輸出含非有限值（NaN／Inf）時回傳 EngineFailure；有輸出像素沒被任何 tile 覆蓋時回傳 ContractViolation。

測試與工具：`tests/core_tests.cpp`（**445 項全部通過**，不需要 GPU）、`runner/tile_runner.cpp`、`scripts/p2_tools.py`、`scripts/nunif_weights_check.py`、`run-p2.ps1`。

- 解讀：差異分布在整張圖（接縫、邊界、內部比例相近），不是集中在接縫。swin_unet 的 window attention 是以 tile 原點來切 window，所以 tile 的切法一改，所有像素的上下文就跟著改變。只是 padding 量不同、切法相同時（300×300 在 T352 與 T400 下都是單一 tile），結果幾乎一樣（83–89 dB，max 1）。
- 小圖在 T64 與 T160 以上的差異只出現在邊界：補邊量不同，影響了邊緣的上下文。
- 結論：沒有可見的接縫瑕疵。但**換 tile 大小會產生不同、而且同樣「正確」的結果**；合成的硬邊圖差異較大，實圖較小（49–55 dB）。

## 8. 尺寸

- 40 組比較的輸出形狀都等於上游（`compare` 會檢查形狀），也就是精確的 W·s × H·s：1×300 → 4×1200、400×3 → 1600×12、37×23 → 148×92、257×131 → 1028×524、2600×1730 → 10400×6920。
- `core_tests` 用假引擎（最近鄰放大後裁掉 offset）對 1×1、1×300、300×1、37×23、257×131、240×240、241×239、700×333，在 1×／2×／4× 與 tile 64／160／256 下比對整張最近鄰放大，**逐位元相同**。這驗證了沒有漏像素、沒有位移、覆蓋完整；進度總和也剛好等於總像素。輸入另外加了 3–5 bytes 的 stride padding，驗證 stride 處理。

## 10. 滿尺寸（noise3_scale4x，2600×1730 → 10400×6920，tile 256，只跑一次）

## 11. 取消

| 情境 | 設定取消的時間 | 從設定到返回 | 結果 |
