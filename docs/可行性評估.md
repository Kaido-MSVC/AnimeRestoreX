# AnimeRestoreX v1.0 可行性評估

Nov 1, 2026 · @YU SIANG CHEN

## 結論：附條件可行

規格範圍與技術方向都做得到，沒有發現會擋住專案的問題，可以交給 Claude Code。動工前，下列 3 件事必須先寫進規格：

1. **依格式檢查單邊上限。** WebP 單邊上限為 16383 px；75 MP 總像素合格不代表長邊合格。例：4500×1000 放大 4× 為 18000×4000，WebP 會寫入失敗。
2. **調高 Qt 讀圖記憶體上限。** 72 MP RGBA 約 288 MB，可能超過 Qt 預設上限而在讀回時被拒；需呼叫 `QImageReader::setAllocationLimit()`（官方範例設為 1024 MB）。
3. **最終編碼交給 Qt。** 上游 README 註明 png／webp 輸出皆為無損編碼，CLI 也沒有品質參數，無法滿足 JPEG／WebP 品質需求。

## 建議技術決策

### 整合路線：子行程包裝上游預編譯 EXE

固定使用 waifu2x-ncnn-vulkan 正式版 **20250915**（tag commit `a86cfb0`）；此版更新了 ncnn、libjpeg-turbo、zlib-ng，前一預發布版另改善舊顯卡 VRAM 用量並支援超大解析度。不直接整合 C++ 程式碼。

處理流程：

1. Qt 讀圖：`setAutoTransform(true)` 處理方向；拒絕 16-bit 與多影格圖片，不默默降位深或取第一格。
2. 轉成 8-bit RGB(A)，寫成暫存 PNG。
3. 以 `QProcess` 參數清單執行 `waifu2x-ncnn-vulkan -i tmp.png -o out.png -n N -s 2|4 -t T -m <絕對路徑>`，不經過 shell。
4. Qt 讀回結果，以 `QImageWriter` 依格式與品質寫成暫存檔，確認成功後才改名為正式檔名。

好處：品質、方向、alpha 與錯誤處理集中在 Qt；推論崩潰不拖垮 GUI；授權範圍單純。代價：沒有逐 tile 進度，單張只顯示「處理中」，v1.0 可接受。關閉視窗或結束工作時須確實結束子行程。參數以實際發行 EXE 的 `-h` 輸出為準（README：`-s` 1/2/4/8/16/32，`-n` -1 到 3）。

### 模型：只散布 models-cunet

- 專為動漫設計，降噪 -1 到 3，原生倍率 2×。
- 4× 以 `-s 4` 實現；須實測是否等於兩次 2×，以及降噪是否只執行一次。
- 設定視窗只開放降噪等級（預設值由實測決定）與 tile（自動／400／200／100）；TTA、多 GPU 不開放。

### 輸出格式：Qt 內建插件

| 格式 | 介面行為 | 依據／備註 |
| --- | --- | --- |
| WebP 有損 | 品質 0–99 | Qt 插件品質 < 100 走有損模式 |
| WebP 無損 | 固定送品質 100，停用品質滑桿 | 品質 = 100 切換無損；壓縮努力程度固定為 libwebp 預設，不另做控制 |
| JPEG | 品質 0–100 | 單邊上限約 65500 px；透明圖合成白底 |
| PNG | 無損 | alpha 保留方式於 A4 實測上游行為 |

### 語言偵測：Win32 API

- 以 `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME)` 取第一個語言，不依賴 `QLocale::system()`。
- 對應：`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant-*` → 繁中；`ja*` → 日文；其他（含 `zh-CN`、`zh-SG`、`zh-Hans`）→ English。
- 切換語言以 `LanguageChange` 事件加 `retranslateUi` 即時重譯。

## GTX 1060 6GB 與尺寸上限

4.5 MP 輸入／75 MP 輸出上限**很可能可保留**，但目前沒有實機數據，A9 實測後才能定案。以下僅為依上游資料的推估：

- 上游以 GTX 1070 測 cunet：4000×4000 → 8000×8000（64 MP），tile 200 約 24 秒，VRAM 約 650 MB。
- 推估 4.5 MP 放大 4×（4.5 → 18 → 72 MP）在 GTX 1060 上約需數十秒到一分多鐘。
- VRAM 不是瓶頸；需實測的是**系統 RAM 峰值**，可能達 GB 等級。
