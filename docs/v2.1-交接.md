## 2. 已定決策

| 項目 | 決策 |
|---|---|
| C++ 標準 | **C++23**，`CMAKE_CXX_STANDARD 23`。CMake 4.4.4 在 MSVC ≥ 19.29.30129 時把 C++23 對應到 `-std:c++latest`，所以在 `project()` 之後覆寫 `CMAKE_CXX23_STANDARD_COMPILE_OPTION`／`CMAKE_CXX23_EXTENSION_COMPILE_OPTION` 為 `-std:c++23`（只限 MSVC ≥ 19.52）。CMake 原生支援之後就移除這段。`tools/winml-probe` 同樣處理。不用 C++26 |
| MSVC 工具集 | **14.52**（14.51 已不在這台電腦上）：`build.ps1`、`tools/package.ps1`、`tools/make-icons.ps1`、probe 的 `build.ps1` 都固定 `-vcvars_ver=14.52`；CRT 取自 `VC\Redist\MSVC\14.52.37025\x64\Microsoft.VC145.CRT`（14.52.37029.0） |
| VC 執行階段 | 封裝內含 6 個：`msvcp140`、`_1`、`_2`、**`_atomic_wait`**（v2.1 起 exe 需要，`std::execution::par` 引入）、`vcruntime140`、`_1`。`package.ps1` 的依賴檢查會擋下來自 System32 的 VC DLL |
| TTA | 照 nunif 0d3d92c：整張 RGB 8 種變換，各自完整 tiled render 後反變換、依序加總、×1/8、clamp；alpha 不做 TTA。設定 `v2/inference/tta`，預設關閉。ETA 速度分組加 `/tta` |
| 灰階 | 自動：來源是灰階（PNG color type 0／4 且 bit depth ≥ 2、JPEG 單元件）就輸出灰階；調色盤 PNG、1 位元 PNG 不算（與 nunif 相同）。強制：`v2/output/grayscale`。公式是 Pillow 的整數 `L24`，不用 `qGray` 或 Qt 的轉換 |
| ICC | **不做色彩轉換**：RGB 描述檔（或灰階來源的 GRAY 描述檔）原樣寫回，像素就是檔案裡的值（nunif 會轉 sRGB 再轉回，本程式不這樣做）。其他描述檔不寫，照舊轉 sRGB。固定行為，沒有選項 |
| EXIF | 「保留 EXIF」`v2/output/keepExif`，預設關閉，UI 註明可能含拍攝位置。寫出前：Orientation 一律 1、PixelX／Y 改成輸出尺寸、移除縮圖（IFD1）；結構損壞就不寫 EXIF，圖照常輸出。不用第三方 EXIF 函式庫 |
| 方向 | JPEG 由 Qt 轉正；PNG／WebP 由 `OrientedReader` 依 EXIF Orientation 轉正（Pillow `exif_transpose` 的對應表）。工作、預覽、清單縮圖共用 `OrientedReader`。只讀 EXIF，不讀 XMP |
| 底片顆粒 | 照 nunif `rgb_noise_like(level=2)` 與 `apply_rgb_noise`，強度就是 nunif 的 `grain_strength`（UI 0.05–1.00，預設 0.20，靜態圖實際套用 ×0.5）。**固定種子**（由輸出尺寸與強度算出，SplitMix64 → Box–Muller），同一張圖、同設定每次相同；上游沒有種子。設定 `v2/output/grain`、`v2/output/grainStrength` |
| 16 位元輸出 | **取消**：不提供 16 位元輸出（使用者判斷 8 位元輸入沒有實益）。輸入的 16 位元圖仍照舊拒絕。管線全程 8 位元，與 v2.0 相同 |
| 設定相容 | 新的鍵都在 `v2/` 底下，舊設定檔沒有這些鍵時視為關閉，不需要遷移；v1.2 的鍵仍然只讀 |
| 授權 | v2.1 沒有新增散布的第三方元件。`THIRD_PARTY_NOTICES` §6 記錄演算法出處：nunif（MIT，已附 `licenses/nunif/LICENSE`）、Pillow 的行為（沒有複製程式碼）、SplitMix64／Box–Muller（自行實作） |

## 3. 已知問題

- **TTA 的時間與記憶體**：約 8 倍時間（2400×1606 2× 實測 5.8 倍，固定開銷不乘 8）。最大尺寸 4× 透明圖峰值 4.4 GB（不開 3.5 GB），README 寫建議 16 GB。
- **TTA 的透明像素**：alpha = 0 像素的 RGB 可能與不開 TTA 差 1（浮點平均跨過量化邊界），這些像素看不到（P2 報告 §4.1）。
- **顆粒的跨平台差異**：`log`／`cos` 在不同的 CRT 可能有最後一位差異，換平台的輸出可能不同；同一台電腦重跑相同。75 MP 開顆粒的時間未實測（推估 +20 s）。
- **含透明的灰階**：PNG／WebP 存成 R=G=B 的 RGBA，不是 LA；灰階透明圖輸出 JPEG 時，合成白底用 Qt 的捨入（未對 Pillow 逐像素比對）。
- **ICC**：不支援色彩管理的看圖軟體看到的輸出與原圖相同；nunif 會寫回 PNG gAMA，本程式不寫。
- **EXIF**：PNG eXIf 不會出現在檔案總管的屬性（Windows 不讀）；超過 64 KB 的 EXIF 寫不進 JPEG（不寫並記錄）；XMP 方向、PNG `Raw profile type exif` 不讀。
- **exe 仍沒有 VERSIONINFO**（v2.0 已知），檔案屬性看不到版本；「關於」、NOTICES、封裝名都由 `CMakeLists.txt` 帶入。
- **SHA256 檔是 CRLF**（v2.0 已知）：Linux 的 `sha256sum -c` 要先 `tr -d '\r'`。
- `tests/tst_inference_core.cpp` 的 C4456 警告（P1 起，未修）。
- 只在 Windows 11 25H2 + GTX 1060 6GB 實測。

## 4. 工作規則

沿用 `docs/v2.0-交接.md` §5，另加：

- 含反斜線的檔案只用 Edit；commit 不加 Co-Authored-By；不動全域工具和 PATH；Qt、ORT、DirectML、模型、manifest 都不動（v2.1 全程沒有動）。
- 建置用 `build.ps1`（VS 2026、**MSVC 14.52**）；`ctest --preset release`，大改動另跑 debug。debug 曾抓到測試本身的未定義行為（P3）。
- **加字串後要跑 lupdate**（`cmake --build build/release --target update_translations`）並確認 zh_TW／ja 沒有 `unfinished`：P3、P4 漏了 2 個，到發布準備才補上。
- 回歸用 `_work/v21base/run-cases.sh`（15 張）＋ `run-timing.sh`（2400×1606）對前一階段的輸出比對，要求最大差 0。
- Pillow 參考一律用 `_work/venv-torch`（Pillow 13.0.0、torch 2.14.1），用 `-I` 執行；`third_party/_download/venv-models` 只給 `fetch-models.ps1` 用。
- UI 截圖：`ARX_UI_SNAPSHOT`；P5 另有 `ARX_UI_SNAPSHOT_ROTATED`（分號分隔的檔案）。
- 用 PowerShell 跑長指令時，不要把輸出接到 `Select-Object -First N`：它會提早結束上游的程序（這次因此中斷過一次封裝）。改成寫進記錄檔再篩選。
