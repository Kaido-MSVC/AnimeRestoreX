寬高數字是表內符號，主模型的 `scale1x.onnx` 另計：兩個都是 2 個節點、不含 Pad，且 app 不使用。

**`swin_unet/art` 也是 dynamo。** 呼叫路徑（nunif `0d3d92c`）：

| 模型 | 呼叫 | 實際的 `torch.onnx.export` | 結果 |
|---|---|---|---|
| swin_unet/art 主模型 | `export_onnx.py:65-72` 沒傳 `dynamo`，`export_onnx.py:22` 預設 `False`，進入 `model.py:90` 的 `else` 分支 | `model.py:115`：**沒有傳 `dynamo`**，只傳 `dynamic_axes` | 用 torch 預設值 `True`，dynamo |
| swin_unet_v3/art 主模型 | `export_onnx.py:124-132` 傳 `dynamo=True`，進入 `if` 分支 | `model.py:99`：明確 `dynamo=True`，用 `dynamic_shapes` | dynamo，不受 torch 預設值影響 |
| `scale1x` | `export_onnx.py:77、135` | `onnx_helper_models.py:260-261`：`dynamo=True` | dynamo |
| utils | `export_onnx.py:143-158` | `onnx_helper_models.py`：`dynamo=False` | TorchScript |

所以 `model.py:90` 的 `dynamo=False` 實際上不會選到舊匯出器，它只決定走哪個分支。

佐證：

- **torch 原始碼**：`torch/onnx/__init__.py:78` 是 `dynamo: bool = True`；docstring 寫明 `versionchanged:: 2.9`「`dynamo` is now True by default」、`versionchanged:: 2.11`「`fallback` option has been removed」。
- **匯出日誌**：`torch.export.export` 共 65 次，等於 72 個檔案扣掉 7 個 utils；`model.py:115` 的 `dynamic_axes` 警告 42 次，等於 art、photo、art_scan 各 14 個主模型。
- **檢查結果**：swin_unet/art 與 v3 都是 IR 10，utils 是 IR 9；art 圖中出現 `Gelu`。

nunif 也沒有傳 `opset_version`，opset 20 來自 torch 的 `ONNX_DEFAULT_OPSET`。因此這批模型的來源要寫成 **nunif `0d3d92c` + torch 2.14.1+cpu + onnx 1.23.2 + onnxscript 0.7.2**，換 torch 版本重新匯出會得到不同的圖。其他 torch 版本的實際結果未執行。

v3 的 int 常數裡有 `[128]`、`[-1, 64, 128]`、`[128, 128, 128]`，看起來是 `middle_dim=128` 與 8×8 視窗（64 個 token），不是匯出時的 tile 尺寸。沒有找到 240／256／480／512 這類值。這只是沒有發現寫死的尺寸，**不能證明**任意 tile 都可執行，P1 要用多種 tile 實測。

### 4.2 運算子

- 新 art 相對舊 art：多 `Gelu`（14 個）、`Squeeze`；少 `Cast`、`Constant`、`Erf`、`Pow`。舊圖把 GELU 拆成 Erf 等基本運算，新圖用 opset 20 的 `Gelu`。
- v3 使用的運算子：Add、And、Clip、Concat、Conv、DepthToSpace、Div、Expand、Gather、IsNaN、MatMul、Mul、Neg、Pad、Pow、Range、Reciprocal、ReduceMean、Reshape、Resize、ScatterND、Shape、Sigmoid、Slice、Softmax、Split、Sqrt、Squeeze、Transpose、Unsqueeze、Where。

## 6. 進入 P1 前還缺什麼

1. **`rewrite_pad.py` 要能處理 v3**：遇到 `edge` 就 STOP。要改成放行 pads ≥ 0 的 edge Pad，只改寫負數的 constant Pad。這輪依指示沒有改腳本。
2. **決定 P1 的 art 版本**：4× 目前只能用 swin_unet/art。作者的指令會產生新圖，但舊 zip 的權重相同，且舊圖已驗證到 P5。依目前決策（不再使用舊 zip），P1 要驗新圖；如果新圖在 DML 上有問題，要回來討論。
3. **P1 要新增的驗證項目**：
   - Windows ML 內含的 ORT 1.28.3 能否載入 IR 10／opset 20。
   - DML 是否完整放置節點，特別是 `Gelu`、`IsNaN`、`Resize`、`Pad edge`。
   - 改寫前後與 CPU、PyTorch 的輸出比對。
   - 多種合法 tile（160、256）與非法 tile 的行為。上游的斷言不會進入 ONNX，舊模型曾有靜默執行的情況（P0-P1 報告 §12.6）。
4. **v3 的 PyTorch 參考輸出**：`_work/nunif-home` 沒有 v3 權重。P1 要用 `--model-dir` 指向這次的 `pretrained_models`，或使用新的 `NUNIF_HOME`。
5. **probe 腳本的路徑**：`run-probe.ps1`、`run-p1fix.ps1` 都寫死 `swin_unet\art`，要讓它們能指向 v3。這些是 P1 的工作，這輪沒有改。
