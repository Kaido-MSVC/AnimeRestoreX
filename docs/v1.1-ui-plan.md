# AnimeRestoreX v1.1 UI 改善規劃

日期：2026-11-02
依據：2026-11-02 以 Impeccable 原則做的 UI 評估（Nielsen 啟發式評分 25/40）

## 範圍與限制

- 維持 Qt Widgets 現有架構，不使用 HTML／CSS／WebView。
- 不新增第三方依賴，不重寫核心處理流程，不擴大 v1.1 功能範圍。
- 依序分三個階段實作，每個階段各自建置、測試、提交一次。
- 不執行 git push，不建立 GitHub Release。

## 已確認的決定

1. 降噪強度移到主畫面；設定對話框只保留「圖塊大小」和「介面語言」。
2. 開始處理的快捷鍵使用 Ctrl+Enter。
3. 跨螢幕 DPI 變化（從 100% 螢幕拖到 150% 螢幕）延後處理，不納入 v1.1。

## 追加需求

### 放大倍率新增「不放大（1×）」

我直接執行 waifu2x-ncnn-vulkan 20250915 驗證過，結果如下：

| 指令 | 結果 |
|---|---|
| `-s 1 -n 0..3` | 支援。使用 cunet 的 `noiseN_model` 純降噪模型，輸出尺寸與原圖相同 |
| `-s 1 -n -1` | 程式會正常結束（exit 0），但不做任何處理，等於只是重新編碼 |
| 模型檔 | 上游 zip 內有 `noise0..3_model.{param,bin}`，但 v1.0 發行包沒有收錄（`tools/package.ps1` 只收 2× 模型） |

實作方式：

- 核心：
  - `Waifu2xRunner::passes()` 遇到 scale 1 時只跑一趟，使用 `noiseN_model`。
  - `checkInstall()` 依每一趟實際使用的模型檢查檔案是否存在。
  - `ProcessJob` 每一趟的預期輸出尺寸改用該趟的倍率計算，不再固定 ×2。
  - `ImageLimits` 接受 scale 1。
  - 輸出檔名為 `name_1x.ext`，沿用現有規則。
- 1× 搭配「不降噪」沒有意義：
  - 介面上「開始處理」會停用，狀態列說明原因。
  - 核心的 `checkPreconditions()` 也會拒絕這個組合，作為第二道防線。
- 發行包：
  - `package.ps1` 加入 `noise0..3_model.{param,bin}`，皆為上游原檔，未修改。
  - 同步更新 `THIRD_PARTY_NOTICES.md` 的檔案清單與 SHA256，並刪除「不包含 1× 純降噪模型」這句說明。
  - 同步更新 `README.md` 和 `packaging/README.txt` 的「2× / 4×」敘述。

### 進度條

現有行為：

- 範圍 = 本次要處理的項目數。
- 每完成一個項目（成功或失敗）加 1；被取消的項目不計入。
- 文字格式為 `%v / %m`；清單清空時重設為 `0 / 0`。

`tst_ui::fullBatchThroughMainWindow` 已驗證跑完 3 項時值為 3、重跑時範圍為 1，`progressResetsWhenListEmpties` 也已驗證重設行為。進度條運作正確，**不修改**。

## 量測基準（v1.0 dist，1920×1080 螢幕）

| 縮放 | 最小視窗（實體像素，含框線） | 預設 1100×720 換算後 | 可用高度 |
|---|---|---|---|
| 100% | 564×465 | 1100×720 | 1032 |
| 125% | 701×579 | 1375×900 | 1032 |
| 150% | 838×687 | 1650×1080，超出可用區域 | 1032 |

問題出在寫死的初始大小，最小尺寸本身沒有問題。**不以調高最小尺寸作為解法。**

## 驗收標準

- 在以下五種組合下，「開始處理」和「取消」都必須完整可見：
  - 1920×1080：100%、125%、150%
  - 1366×768：100%、125%
- 中、日、英三種語系下，`minimumSizeHint()` 加上框線都不超過 **620×500 邏輯像素**。

## 第一階段：高 DPI 與視窗縮放

1. **初始大小**：新增純函式 `fitWindowRect(preferred, minimum, available)`。
   - 取偏好大小 1100×720 與可用區域 90% 的較小值，但不小於最小尺寸；最後置中。
   - 用 `QGuiApplication::screenAt(QCursor::pos())` 決定螢幕，找不到時退回主螢幕。
2. **記住視窗**：`AppSettings` 新增視窗幾何與分割比例的存取，在 `closeEvent` 儲存。
   - 還原後再用第 1 點的函式夾一次大小，避免上次存的大小超出這次的可用區域。
   - 讀不到或資料損毀時，改用第 1 點的算法。
3. **狀態列**：改用 `QMainWindow::statusBar()`，放一個單行、超長時自動加省略號的 label（新增小類別 `ElidedLabel`），完整文字放 tooltip。
   - 原因：原本會自動換行的 label 遇到長訊息時，會把最小高度撐大。
4. **清單欄寬**：「詳細資訊」欄寬隨清單寬度變化，取檢視區寬度的 30%，上下限以字寬換算，確保檔名欄保有大部分空間。
5. **寫死的像素值改成依字型計算**：AboutDialog、CompletionDialog、PreviewPane 的最小尺寸，以及表頭寬度。
   - AboutDialog 的圖示改用會傳入 device pixel ratio 的 `pixmap` 多載，高 DPI 下才清晰。

## 第二階段：版面與操作流程

1. 下方設定區拆成「處理」（放大倍率、降噪強度）和「輸出」（資料夾、格式、品質）兩組，左右並排，高度與 v1.0 相同。
2. 降噪強度從設定對話框移到主畫面，設定的儲存位置不變。
   - 改變降噪時，已完成的項目一樣會重設成待處理。
3. 品質欄位在 PNG 或 WebP 無損時直接隱藏，原本的提示文字改成 tooltip。
   - 隨格式出現或消失的控制項排在該列最後，切換格式時前面的控制項不會移位。
4. 「開始處理」設為預設按鈕，文字帶出待處理數量。
5. 「預覽」下拉選單移到「處理結果」標題那一列的右側，省下的一列高度用來抵掉第一階段新增的狀態列。
   - 「原圖」「處理結果」兩個標題改成粗體。
6. 空狀態：
   - 清單是空的時候，在清單中央顯示提示文字。
   - 預覽區依「清單是空的」或「尚未選取」分別顯示不同訊息。
7. 用語與選單：
   - 中文版 Details 欄改叫「詳細資訊」，避免和「說明」選單同名。
   - 選單改成「檔案／工具／說明」三個。
   - 「失敗」狀態加上系統錯誤圖示，不再只靠紅字區分。

完成對話框的行為不變，不更換配色，也不套用 QSS 主題。

## 第三階段：拖放與快捷鍵

1. **拖放**：主視窗接受拖放（`setAcceptDrops`），拖到清單上的事件會往上傳給主視窗處理。
   - 檔案交給 `addFiles()`。
   - 資料夾由背景工作依序掃描後加入，掃描邏輯從 `browseFolder` 抽出共用。
   - 處理中或掃描中拒絕拖放。拖動經過時清單外框以強調色標示。
   - 拖放不會改動記住的「上次匯入資料夾」。
2. **快捷鍵**：

   | 動作 | 快捷鍵 |
   |---|---|
   | 匯入圖片 | Ctrl+O |
   | 匯入資料夾 | Ctrl+Shift+O |
   | 開始處理 | Ctrl+Enter |
   | 移除選取 | Delete（清單有焦點時） |
   | 設定 | Ctrl+, |

   - 取消處理不設快捷鍵，避免誤觸中斷長時間處理。
   - 按鈕加上助記鍵：中文與日文用 `(&X)` 後綴格式。
3. 空狀態的提示文字加上拖放說明。

## 測試

- **自動測試**（`tst_ui`，使用隔離的 INI 設定，不會寫入使用者登錄）：
  - `fitWindowRect` 在五種螢幕情境下的結果。
  - 視窗幾何儲存後讀回一致、資料損毀時退回預設。
  - 三語系的最小尺寸都在上限內。
  - 降噪與品質欄位的行為。
  - 1× 搭配不降噪時禁止開始。
  - 拖放與 Delete 鍵。
- **核心測試**（`tst_core`／`tst_pipeline`）：1× 的處理趟數、模型檔檢查，以及實際用 waifu2x 跑一次 1×。
- **截圖驗證**：用 `QT_SCALE_FACTOR` 1.0、1.25、1.5、2.0 截取 dist 版畫面；三語系截圖透過 `ARX_UI_SNAPSHOT` 存到暫存目錄，不提交進 repo。
- **人工驗證**：請使用者把 Windows 顯示縮放實際切換到 125% 和 150%，各開一次 dist 版確認。
