## 4. 已知問題與注意事項

- **887A0020**（DRIVER_INTERNAL_ERROR）只在診斷模式出現過，一般執行沒有遇過。
- **tile 640 會讓 GTX 1060 6GB 的裝置停止回應**（4×），所以不提供 640 以上。
- **tile 大小會影響輸出**：上游 swin_unet 本身的特性，例如 4× 合成圖 t160 對 t256 為 35.8 dB。降到 160 的項目會在清單與完成摘要中標示。
- **編碼中取消要等編碼做完**：4× WebP 無損最多約 6 s；不會留下輸出檔或 `.tmp`。
- **4× 透明圖約用 2.1 GB** private memory（RGB 與 alpha 兩個 Session 並存）；建議 8 GB RAM。
- DML 用過之後約有 280 MiB 的固定殘留，不會隨張數增加（P3 實測 49 張）；CPU 沒有這種殘留。
- 每批第一張會慢 4–6 s（建立 Session、檢查雜湊），ETA 另外用 `#cold` 學習。
- 只在 Windows 11 25H2＋GTX 1060 6GB 上實測過；Windows 10、AMD／Intel GPU、多 GPU（固定使用預設轉接器）都沒有測。
- 2026-11-03 P3 截圖時，曾用舊的遷移程式改動過使用者實際的設定（`model/tileSize` 與 `progress/` 已遺失，無法還原）；P4 的遷移已改成不破壞。
- 真實測試圖只放在 `tools/winml-probe/_work/test-images`，不得提交。

v3 換代的已知事項（標「程式碼」的項目是唯讀 `_work/upstream/nunif` @ `0d3d92c` 得到的，還沒有實際匯出或執行；P1 要以實際匯出的 commit 重新確認）：

- **swin_unet_v3/art 只有 1×／2×**（noise0–3、noise0–3_scale2x、scale2x），沒有 4×；4× 仍只有舊的 swin_unet/art。程式碼：`export_onnx.py` 沒有 v3 的 4× 路徑，`swin_unet_v3.py` 雖然定義了 `SwinUNet4xV3`，但不會匯出。20260816 修補包的實際內容要在下載後確認。
- **v3 以 dynamo 匯出**，能否在 ORT（Windows ML 內含版本）＋ DirectML 上執行，須在 P1 實測。
- **v3 的 tile 尺寸、offset、blend_size** 必須讀 nunif 的 swin_unet_v3 模型定義重新確認，不可沿用 swin_unet 的契約。
- **手動 tile 400 可能不適用 v3**。程式碼：v3 的條件是 `T >= 64 且 T % 32 == 0`，舊模型是 `T > 16 且 (T − 16) % 48 == 0`。160、256 兩邊都合法，400 只有舊模型合法。`ModelContract::isValidTile`、`core::isOfferedTile` 目前都是單一規則，採用 v3 時要改成依模型判斷。offset／blend_size 的數值與舊模型相同（1×：8／4；2×：16／8）。
- **負數 Pad 問題要重新檢查**：`rewrite_pad.py` 是針對舊模型寫的，不能假設 dynamo 匯出的圖不需要改寫，或改寫後一定正確。程式碼：`swin_unet/art` 在 `export_onnx.py` 仍用舊匯出器（`dynamo=False`），所以重新匯出的 4× 不會得到 dynamo 版本，P1 仍要檢查。
- 重新匯出後所有檔案的雜湊都會改變，舊模型的 P2–P5 像素比對結果不能直接沿用。

## 5. 工作規則

- 不動標籤、Release、`main`，也不推送遠端（除非使用者明確要求）；只在 `v2.0-prep` 上提交。
- commit 不加 Co-Authored-By。
- 手動啟動 app 一律用 `--settings-dir <暫存資料夾>`；截圖走 tst_ui 的 `ARX_UI_SNAPSHOT`（測試本身就用隔離的設定）。
- 大型檔案與中間產物放在 `tools/winml-probe/_work/`（不進 git），例如：P3 的驗證輸出 `_work/p3/`、P2 的參考輸出 `_work/p2/`、2.4.89 的 DLL `_work/build-2.4.89/`。測試用的 staging 複本也建在 `_work/` 底下，測完刪除；不在 `build/` 裡替換 DLL。
- 建置：`build.ps1`（VS 2026、MSVC 14.51、`release` preset）；測試：`ctest --preset release`；`tests/arx_verify` 是用真實引擎做實機驗證的工具（不在 ctest 中）。
- 未執行的項目寫「未執行」；涉及程式庫用法時先查 Context7，報告最後列出查過的文件。
- 檔案一律用 Edit／Write 寫入；寫入含 Windows 路徑的檔案後，檢查有沒有控制字元。

## 6. 模型來源：自行用 nunif 匯出

依據：nunif 作者 2026-11-03 的回覆（`docs/licenses/inquiries.md` §1）。**尚未執行**：本節只是計畫，還沒有 clone、下載或匯出。這裡的 P0／P1 是指換代後重做，不是 §1 中舊模型已通過的階段。

匯出流程（全部放在 `tools/winml-probe/_work/nunif-export/`，已在 `.gitignore` 範圍內，不提交二進位檔）：

1. clone nunif，記錄 commit。
2. 建隔離 venv，安裝 PyTorch CPU 版（torchvision ≥ 0.15），記錄實際版本。匯出還需要 nunif `requirements-dev.txt` 中的 `onnx`、`onnxscript`。
3. 用官方腳本下載 pretrained models（`python -m waifu2x.download_models`），確認 `waifu2x/pretrained_models/swin_unet_v3/art` 存在。
4. 執行 `python -m waifu2x.export_onnx -i ./waifu2x/pretrained_models -o ./waifu2x/onnx_models`。

注意：

- 執行時不要設定 `NUNIF_HOME`，也不要沿用 `_work/nunif-home`：那裡的 20260816 標記檔是 P2 刻意放的空殼，下載腳本看到後會略過 v3，`swin_unet_v3/art` 就不會出現。
- 匯出腳本沒有選擇模型的參數，會把 cunet、photo 等全部匯出，只取需要的檔案即可。
- 切換來源後要跟著改的檔案：`models/manifest.json`、`tools/fetch-models.ps1`、`tools/package.ps1`（來源字串）、`tools/collect-licenses.ps1`（nunif `LICENSE`／`NOTICE` 目前固定在 `31c0137`，要改成匯出用的 commit）、`licenses/README.md`。
