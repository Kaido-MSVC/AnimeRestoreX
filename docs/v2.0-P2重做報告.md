## 4. 重驗

### 4.1 大圖（`sakura_2400x1606`，3.85 MP）

走 `arx_verify`（真實 `ProcessJob`／`BatchRunner`／`EngineHost`），tile 256，PNG，對 PyTorch 同 tile 的切塊結果：

| 模型族 | EP | 時間 | PSNR | 8 位元最大差 |
|---|---|---|---|---|
| v3 1×（noise3） | DML | 16.5 s | 99.52 dB | 1 |
| | CPU | 156.4 s | 99.79 dB | 1 |
| v3 2×（noise2_scale2x） | DML | 23.2 s | 97.28 dB | 1 |
| | CPU | 159.8 s | 96.67 dB | 1 |
| 舊 4×（noise3_scale4x） | DML | 40.4 s | 94.04 dB | 1 |
| | CPU | 122.6 s | 94.22 dB | 1 |

執行環境確認是 ORT 1.24.4。CPU 的 1×、2× 跑的時候有其他測試同時在用電腦，時間偏高。

**v3 alpha（先前未執行，本輪補上）**：`06_chibi_transparent`，2×，DML，對 nunif CLI：RGB 98.07 dB、alpha 103.97 dB，最大差都是 1。

### 4.2 ctest

5／5 通過（`tst_core`、`tst_inference_core`、`tst_pipeline`、`tst_ui`、`tst_ui_layout`），含真實 runtime 的項目。新增：v3 規則、`tile_rule` 驗證、400 遷移、`LicensesDialog`（清單、BOM、缺檔、三語）。

### 4.3 取消

2×，3 秒後在推論中取消：150 ms 返回，沒有留下輸出。維持在 tile 之間取消。

### 4.4 OOM 與裝置錯誤

用 `tile_runner_anytile` 以 tile 1600 跑 v3 noise2_scale2x，走真實的 `upscaleImage` 重試路徑。P2～P4 都沒有實機觸發過。

| 步驟 | 結果 |
|---|---|
| tile 1600 第一次 Run | 8007000E，分類成 OutOfMemory；VRAM 峰值 13.1 GB（含共用記憶體） |
| 同一 session 改用 160 | **887A0006，分類成 DeviceLost**，exit 6，沒有崩潰，沒有輸出 |
| 新程序 tile 256 | 正常（12 個 tile，2.3 s） |

分類與停止都符合決策，但**重做沒有成功**：OOM 之後 D3D 裝置已壞，重用同一個 session 就失敗。主程式走同一段程式碼，所以 Auto 遇到真實 OOM 時預期是停止批次，而不是用 160 完成。這次是用極端 tile 強迫的，一般 256 的 OOM 是否相同未驗證。沒有資料遺失。

解壓封裝，環境變數縮到系統基本項目（`PATH` 只有 Windows 資料夾），工作目錄 `C:\Windows`，用 schema 1、tile 400、已接受 EULA 的舊 INI 以 `--settings-dir` 啟動。這是近似環境，不是 Sandbox 或 VM。

## 5. LICENSE-CODE.txt 結論

**不需要隨附。**

- 套件 `README.md` 明寫：`LICENSE.txt` 適用 `bin/`，`LICENSE-CODE.txt`（MIT）適用 `include/` 與 `build/`。
- 我們只散布 `bin/x64-win/DirectML.dll`，適用 `LICENSE.txt`，已隨附，連同 `ThirdPartyNotices.txt`。
- `include/`、`build/` 都不散布，也沒有進入建置：include path 只有 ORT 套件；ORT 的 `dml_provider_factory.h` 引用的 `DirectML.h` 來自 Windows SDK。
- MIT 的聲明義務隨著複製該軟體而來，這裡沒有複製。日後若改用套件的 `include/` 或 `build/`，再收進來。

這是依套件文字與實際建置做的判斷，不是法律意見。

## 6. 授權檔處理

- ONNX Runtime、DirectML、nunif 的文字是上游檔案原樣複製，不是 `D:\licenses` 的範本：這些檔案帶有該專案自己的版權行，`D:\licenses\README.md` 也要求打包第三方元件時附上對方的條文。`D:\licenses` 內容未修改。
- `tools/collect-licenses.ps1` 已更新，固定 4 個 runtime 檔案的雜湊與 nunif `0d3d92c`；**重新收集未執行**，檔案是直接從已驗證的套件複製，雜湊相符。
